# CLEF CheckThat! 2026 — Task 2: Problem, Data, and Classification Model

*Working overview for the ECIR long paper. Last updated: 27 Sep 2026.*

---

## 1. The Problem

### 1.1 What the task is

CheckThat! 2026 Task 2 is **numerical claim verification**: given a factual claim that hinges on a
number, quantity, statistic, or temporal expression, decide whether the claim is supported by
evidence.

The task ships with **LLM-generated reasoning traces** per claim, and is scored on two fronts:

| Sub-problem | Output | Metric |
|---|---|---|
| **A. Verdict classification** | One label per claim | Macro-F1 |
| **B. Reasoning-trace ranking** | Ranked list of the 15–20 traces attached to each claim | Recall@5 |

For sub-problem B, a trace counts as *relevant* when the verdict stated inside that trace matches
the gold verdict for the claim. If none of a claim's traces is relevant, Recall@5 for that claim is
defined as 0 — so the metric is bounded below by how often the trace pool contains a correct
verdict at all.

### 1.2 Why it is hard

- **Numerical reasoning is not lexical.** Two claims can share almost every token and differ only in
  a magnitude, a unit, or a date, which flips the verdict. Embedding-similarity signals that work
  for generic fact-checking degrade here.
- **The evidence is noisy and redundant.** Each claim comes with many reasoning traces generated by
  an LLM; several may be wrong, several may be right for the wrong reason, and they disagree with
  each other. Aggregating them is itself a modelling problem.
- **Cross-lingual gap.** The same pipeline must hold up across English, Arabic, and Spanish. Signals
  calibrated on English degrade sharply on the other two.
- **Class imbalance and label granularity.** `Conflicting` is rare and is absent from some language
  splits entirely.

### 1.3 Intended pipeline shape

```
Claim
  → Decomposition
  → Evidence Retrieval
  → LLM Reasoning Traces
  → Trace Ranking
  → Final Verdict
```

The paper's contribution sits in the last two stages: how traces are ranked, and how a ranked set of
traces is collapsed into a single verdict.

## 2. The Data

### 2.1 Splits

| Language | Train | Val | Test |
|---|---:|---:|---:|
| English | 6,400 | 1,600 | 2,558 |
| Arabic | 2,608 | 652 | 511 |
| Spanish | 2,608 | 652 | 511 |

### 2.2 Labels

- **English / Spanish:** three-class — `True`, `False`, `Conflicting`.
- **Arabic:** the gold labels contain **no `Conflicting` instances**. For the current phase of the
  paper the Arabic setup is therefore treated as **binary classification (True / False)**.

> **Open decision:** whether the final paper reports Arabic as binary throughout, or forces a
> three-class head with an empty class for comparability with English/Spanish. Currently: binary.

### 2.3 Per-claim structure

Each claim carries:

- the claim text,
- a set of **15–20 LLM reasoning traces**, each containing a chain of reasoning and a verdict it
  argues for,
- the gold verdict.

This gives two usable signal types beyond the claim text itself:

1. **Trace content** — what each trace argues and why.
2. **Trace agreement structure** — the distribution and spread of verdicts across the trace pool,
   which turns out to be informative on its own (see §3.2).

### 2.4 Related data lineage

The work traces back to **CLEF 2025 Task 3**, where a RAG system with zero-shot Qwen-2.5-7B-Instruct
placed **7th of 83 teams** (Macro-F1 0.4749). Generalization beyond the QuanTemp/CheckThat
distribution is being probed against external numerical-claim benchmarks.

## 3. The Classification Model

### 3.1 Representation

- Claims and traces are encoded with **Qwen3-Embedding-8B**.
- **F2LLM-4B** was evaluated as an alternative encoder in a clustering study across SVD
  dimensionalities; Qwen3-Embedding-8B was retained.
- Traces for a claim are pooled into a single claim-level representation. Both **attention pooling**
  over the trace set and a no-attention (mean/concat) variant were tested.

### 3.2 Feature blocks

| Block | Description |
|---|---|
| **Pooled trace embeddings** | Attention-pooled or flat-pooled Qwen3 embeddings over the claim's traces |
| **Disagreement features** | Masked standard deviation across trace embeddings — captures how much the trace pool disagrees, independent of what it says |
| **Verdict scalars** | Engineered features from the per-trace verdicts (distribution, majority margin) |
| **Verdict expansion** | Low-dimensional verdict signal is widened to match embedding scale, via three strategies: cyclic duplication, autoencoder, and a learnable projection |

The verdict-expansion step exists because the raw verdict signal is a handful of dimensions sitting
next to a 4096-d embedding block, and gets swamped without it.

### 3.3 Architecture

Primary classifier: a **PyTorch MLP** over the concatenated feature blocks, trained with
`DataParallel` on **2×T4 GPUs (Kaggle)**.

A **24-experiment ablation grid** crossed:
- attention pooling ∈ {on, off}
- disagreement features ∈ {on, off}
- verdict expansion ∈ {cyclic duplication, autoencoder, learnable projection}
- expansion width ∈ {…, 1024, …}

A parallel **XGBoost** track fused the same ablation features as a non-neural comparison.

### 3.4 Results so far

| Model | Configuration | Macro-F1 |
|---|---|---:|
| MLP | NoAttn + Dup_1024 | **≈ 0.597** |
| XGBoost | NoDisag + AE_1024 | ≈ 0.588 |

Notable: the best MLP configuration **drops attention pooling**, and the best XGBoost configuration
**drops disagreement features** — neither of the two "sophisticated" components survives in its own
best run, which is itself a finding worth reporting.

### 3.5 Trace ranking (sub-problem B) — status

| Approach | Status |
|---|---|
| Claim–trace cosine similarity | Acceptable on English, **poor on Spanish and Arabic** |
| Qwen3-Reranker-8B | Low Recall@5 |
| RankFormer-based ranker | Under exploration |
| **Jev** (TypeSafe AI, via Vercel AI Gateway) | Rank traces by Jev's *P(label \| claim, evidence)* for each trace's asserted verdict. Running on English first. |
| **LLM-as-judge** | Qwen3-8B ranks all traces for a claim; **IRV / Borda / MRR voting** over the rank-ordered trace verdicts produces the final verdict. Evaluated on the test split with Recall@5. |

The last row closes the loop between the two sub-problems: the ranking output is not just scored on
Recall@5, it is also consumed as a voting input to produce the verdict — so a better ranker should
lift Macro-F1 as well.
